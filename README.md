# PioDocker

Local Docker environment for the full [Pioreactor Inc.](https://pioreactor.com/) stack — an open-source bioreactor for microbial cultivation — without needing any Raspberry Pi hardware.

## What is this?

Pioreactor Inc. is an automated bioreactor platform that normally runs its software on a Raspberry Pi with custom HAT hardware. **PioDocker** recreates the entire software stack — including leader/worker cluster topology, web UI, MQTT message bus, job scheduler, and experiment profiles — running entirely in Docker containers with `TESTING=1`, which substitutes GPIO, I2C, ADC, and other hardware interfaces with simulated implementations.

## Architecture

Two services are always started and connect via a shared `lab-network`; workers are optional and generated by `compose.sh`:

- **mosquitto** — MQTT broker (Eclipse Mosquitto). Acts as the central message bus. All job commands, sensor data, OD readings, dosing events, and logs flow through MQTT topics in the format `pioreactor/{unit}/{experiment}/{job}/{metric}`.

- **backend (pio01)** — Cluster leader. Runs Flask (API + pre-compiled React SPA) on port 4999, SSH on 2222, a Huey consumer (8 workers) for background tasks, and an MQTT-to-DB streaming process that persists data to SQLite.

- **worker01..worker0N** — Optional remote workers (default: `WORKER_COUNT=1` starts `worker01`; set `WORKER_COUNT=0` for leader-only). Each runs Flask on port 4999, SSH on `222N` (worker01 → 2223), and a Huey consumer (4 workers). They do not initialize the main database or run MQTT-to-DB streaming. They communicate with the leader exclusively via MQTT.

The **leader** orchestrates experiments: assigns jobs to itself and workers via HTTP (`/unit_api/jobs/run/...`) or MQTT. The React frontend is served as static files from Flask, and the browser connects to the MQTT broker via WebSocket on port 9001.

## Prerequisites

- Docker and Docker Compose installed
- Create the external network before starting:
  ```bash
  docker network create lab-network
  ```

## Quick start

`./compose.sh` is a wrapper around `docker compose` that generates the worker services, syncs the leader's `[cluster.addresses]`, and passes `WORKER_NAMES` to the backend.

```bash
# Create the external network (if it doesn't exist)
docker network create lab-network

# Build and start the stack (default: leader + worker01)
./compose.sh up --build
```

Workers are **optional**: `worker01` is included by default (`WORKER_COUNT=1`), but you can start the leader alone or with more workers:

```bash
WORKER_COUNT=0 ./compose.sh up --build   # leader only (pio01), no workers
WORKER_COUNT=3 ./compose.sh up --build   # leader + worker01 + worker02 + worker03
```

Access the UI at: **http://localhost:4999**

Stop with `./compose.sh down`.

## Services

### Default (always started)

| Service | Port(s) | Role | Volumes |
|---|---|---|---|
| `mosquitto` | 1883 (MQTT TCP), 9001 (MQTT WebSocket) | MQTT message broker | `mosquitto/mosquitto.conf` |
| `backend` | 4999 (Flask/UI), 2222 (SSH) | Leader pio01 — API, UI, jobs, DB streaming | `.pioreactor/` |

### Optional workers (`WORKER_COUNT`, generated by `compose.sh`)

| Service | SSH port | Role | Volumes |
|---|---|---|---|
| `worker01` | 2223 | Worker — executes jobs assigned by the leader | `.pioreactor-worker/` |
| `worker02` | 2224 | Worker | `.pioreactor-worker-worker02/` |
| `worker0N` | `222N` | Worker | `.pioreactor-worker-worker0N/` |

## Configuration

### Key environment variables

| Variable | Value | Purpose |
|---|---|---|
| `TESTING` | `1` | Enables mock hardware (GPIO/I2C/ADC) |
| `HOSTNAME` | `pio01` / `worker01` | Identifies the unit |
| `MODEL_NAME` | `pioreactor_20ml` | Bioreactor model |
| `MODEL_VERSION` | `1.1` | Model version |
| `HARDWARE` | `1.2` | Hardware hat version |
| `BLINKA_FORCECHIP` | `BCM2XXX` | Forces Blinka to use RPi chip profile |
| `BLINKA_FORCEBOARD` | `RASPBERRY_PI_3A_PLUS` | Forces Blinka to use RPi board profile |

### Configuration files

- **`.pioreactor/config.ini`** — Leader configuration.
- **`.pioreactor-worker/config.ini`** — worker01 configuration (`cluster.topology.leader_address=backend`) and template for extra workers.
- **`.pioreactor-worker-worker0N/`** — worker02+ configurations, generated from the template by `compose.sh`.
- **`mosquitto/mosquitto.conf`** — MQTT broker: ports 1883/9001, anonymous access, persistence enabled.

### MQTT connection

- Broker: `mosquitto` (Docker DNS, rewritten to `localhost` for browser access)
- TCP: port 1883 | WebSocket: port 9001
- Mosquitto allows anonymous access by default

## Usage

### Running experiments

Experiment profiles are located in `.pioreactor/experiment_profiles/`:

- **`profile_initial.yaml`** — Stirring (500 RPM), thermostat (30°C), and OD reading
- **`profile_dosing.yaml`** — Adds media dosing (0.5ml) and waste removal (1.0ml) hourly

```bash
./compose.sh exec backend pio run experiment_profile execute .pioreactor/experiment_profiles/profile_initial.yaml <experiment_name>
```

### CLI commands

```bash
./compose.sh exec backend pio run <job_name>
./compose.sh exec backend pio kill --all-jobs
./compose.sh exec backend pio logs -n 10
./compose.sh exec backend pio mqtt
```

### Testing

```bash
./compose.sh exec backend pytest core/tests
```

### SSH access

```bash
ssh -p 2222 pioreactor@localhost   # backend
ssh -p 2223 pioreactor@localhost   # worker01 (if started)
```

## Gotchas

1. **External network required**: `docker network create lab-network` must exist before `./compose.sh up`.
2. **MQTT address rewriting**: `local_app.py` rewrites `broker_address=mosquitto` → `broker_address=localhost` in `/api/config/shared` so the browser can reach the WebSocket on `:9001`.
3. **Generated override**: `.compose-workers.yml` is regenerated on every `compose.sh` run — edit `compose.sh` (or `WORKER_COUNT`) instead.
4. **Ephemeral state**: Entrypoints regenerate hardware YAML, DB, calibrations, and UI descriptors on every start. Only `config.ini` is tracked in git.
5. **Upstream patches**: Dockerfiles patch `export_experiment_data.py` to use `DOT_PIOREACTOR` instead of relative paths.
