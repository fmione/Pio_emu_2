# PioDocker — Pioreactor Local Emulator

Locally emulate via Docker the full Pioreactor stack without Raspberry Pi hardware. `TESTING=1` substitutes GPIO/I2C/ADC.

## Architecture

- **4 services** in `docker-compose.yml`: `mosquitto`, `backend` (leader pio01), `worker01`, `emulator`.
- Backend exposes Flask on `:4999` (host) and SSH on `:2222`. Worker exposes SSH on `:2223`.
- Workers run as separate containers, **not** processes inside backend.
- Both containers run `flask --app <local_app|worker_app> run -p 4999`.
- Huey uses **SqliteHuey**, not Redis. Consumer: `-w 8` (backend) / `-w 4` (worker).
- MQTT is the message bus. Frontend is pre-compiled React served by Flask (SPA catch-all in `local_app.py:27`).
- **Emulator** runs a standalone ODE-based bioreactor simulation, publishing OD/glucose data via MQTT.
- Network `lab-network` must exist externally: `docker network create lab-network`.

## Key files

| File | Purpose |
|---|---|
| `Dockerfile.backend` / `entrypoint.sh` | Leader image — creates hardware YAML, DB, calibrations, registers workers, clears stale MQTT states, starts Huey + MQTT-to-DB + Flask |
| `Dockerfile.worker` / `entrypoint-worker.sh` | Worker image — same setup but no DB init, no MQTT-to-DB streaming |
| `Dockerfile.emulator` | Emulator image — Python + numpy/scipy/pandas + paho-mqtt |
| `local_app.py` | Wraps upstream `create_app()` with SPA catch-all + MQTT broker address rewrite (`mosquitto` → `localhost`) |
| `worker_app.py` | Thin wrapper around `create_app()` |
| `emulator/cli.py` | CLI: `start`, `stop`, `status`, `reset` |
| `emulator/main.py` | Execution loop: calls model `start_EXP()` / `run_emu()`, then exposes data via MQTT |
| `emulator/model/` | **Verbatim copy** of the Airflow `emulator_dag` scripts — NEVER edit. Runs on its own (CWD = model dir) and generates the JSON/CSV files |
| `emulator/mqtt.py` | Reads `model/db_emulator.json`, diffs vs `last_published.json`, publishes new OD/glucose/feed points via MQTT |
| `emulator/db.py` | SQLite direct access (init + clean experiment) |
| `emulator/model/EMULATOR_config.json` | Simulation parameters (IC, kinetics, feed profiles), generated by running `model/Create_Design.py` |

## `emulator/model/` contract

- Contains **all** files of `Pio_emu_model2/dags/scripts/emulator_dag/` copied byte-for-byte: `Create_Design.py`, `Node_start_emulator.py` (`start_EXP`), `Node_run_emulator.py` (`run_emu`), `method_emulator.py`, `function_simulation.py` (6-state ODE: `Xv, Glucose, Ethanol, V, e, Si`), `function_aux_profile.py`, `pioreactor_db.py` (not used for now), `Plot_emulator_state.py`, `Test_emu.py`, `db_emulator_template.json`, `measurements_atline.csv`.
- **Do not modify anything inside `emulator/model/`.** External modules (`main.py`, `mqtt.py`, `db.py`, `cli.py`) only call its functions and read the JSONs it produces.
- These files use CWD-relative paths, so `main.py` does `os.chdir(MODEL_DIR)` before importing them (`from Node_start_emulator import start_EXP`, `from Node_run_emulator import run_emu`).
- The model **generates** `EMULATOR_state.json`, `EMULATOR_design.json`, `db_emulator.json`, `measurements_atline.csv` inside `emulator/model/` (writable bind-mount). These are gitignored.
- Config: run the unmodified `Create_Design.py` to (re)generate `model/EMULATOR_config.json`:
  `docker compose run --rm -w /app/model emulator python Create_Design.py` (override the entrypoint with `--entrypoint python` if run via `docker run`).
- `pioreactor_db.py` (SSH-based) is copied but **not used**: DB writes are done via `emulator/db.py` (direct SQLite) and data exposure via MQTT.

## Development commands

```
docker compose up --build                          # full stack
docker compose up -d emulator                      # start emulator only
docker compose exec emulator python -m emulator.cli status   # check status
docker compose exec emulator python -m emulator.cli stop     # graceful stop
docker compose exec emulator python -m emulator.cli reset    # clear state, restart
docker compose exec backend pio run <job>          # launch job
docker compose exec backend pio kill --all-jobs     # kill all jobs
docker compose exec backend pio logs -n 10         # recent logs
docker compose exec backend pio mqtt               # live MQTT feed
```

## Config & state

- `.pioreactor/config.ini` — leader config. Tracked in git.
- `.pioreactor-worker/config.ini` — worker config (points `cluster.topology.leader_address=backend`). Tracked.
- `.gitignore` treats `storage/`, `hardware/`, `ui/`, `plugins/`, `exportable_datasets/`, `experiment_profiles/` as ephemeral (regenerated by entrypoints). Worker dir is almost entirely ephemeral except `config.ini`.
- Both `config.ini` files set `broker_address=mosquitto` (Docker DNS).
- Entrypoints auto-create hardware YAML, SQLite DB, calibrations, worker registrations, and clear stale retained MQTT states on each start.
- **Emulator state** persists in `emulator/state/` (mounted volume: pid, stop flag, `start_datetime`, `last_published.json`). Survives container restarts.
- **Model runtime files** (`EMULATOR_state.json`, `EMULATOR_design.json`, `db_emulator.json`, `measurements_atline.csv`) persist in `emulator/model/` (writable bind-mount).
- **Emulator config** lives in `emulator/model/EMULATOR_config.json` (mounted volume), generated by `Create_Design.py`.

## Emulator service

The emulator replaces the old Airflow DAG. It runs as a standalone Docker container:

1. `emulator start` — cleans DB, initializes experiment, runs model `start_EXP()`, starts loop
2. Loop: model `run_emu()` (ODE integration → sample with noise → persist JSONs + CSV) → publish new MQTT points → sleep
3. Model state persists to JSON files in `emulator/model/`
4. Survives power cuts via `restart: unless-stopped` + state persistence
5. `emulator stop` — writes stop flag, exits gracefully
6. `emulator reset` — clears state/ + model runtime files, ready for new experiment

## Testing

- `docker compose exec backend pytest core/tests` (runs upstream Pioreactor tests inside container).

## Gotchas

- Run `docker network create lab-network` before first `docker compose up`.
- `local_app.py` rewrites `broker_address=mosquitto` → `localhost` in `/api/config/shared` so the browser JS can reach MQTT via WebSocket on `:9001`.
- `test-mqtt-cli` contains a one-shot `mosquitto_pub` command to inject fake OD data for manual testing.
- Emulator must be stopped before `reset` (or it will fail).
- After power cut, emulator resumes from last checkpoint automatically.
