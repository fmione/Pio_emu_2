# PioDocker — Pioreactor Local Environment

Locally run via Docker the full Pioreactor stack without Raspberry Pi hardware. `TESTING=1` substitutes GPIO/I2C/ADC.

## Architecture

- Base `docker-compose.yml` has 2 services: `mosquitto`, `backend` (leader pio01). The N workers (`worker01`..`worker0N`) are generated by `compose.sh` into `.compose-workers.yml`.
- Backend exposes Flask on `:4999` (host) and SSH on `:2222`. Each worker `worker0N` exposes SSH on host port `222N` (worker01 → 2223).
- Workers run as separate containers, **not** processes inside backend.
- Both containers run `flask --app <local_app|worker_app> run -p 4999`.
- Huey uses **SqliteHuey**, not Redis. Consumer: `-w 8` (backend) / `-w 4` (worker).
- MQTT is the message bus. Frontend is pre-compiled React served by Flask (SPA catch-all in `local_app.py:27`).
- Network `lab-network` must exist externally: `docker network create lab-network`.

## Key files

| File | Purpose |
|---|---|
| `compose.sh` | `docker compose` wrapper — generates `.compose-workers.yml` with N workers based on `WORKER_COUNT` (default 1), syncs the leader's `[cluster.addresses]`, and passes `WORKER_NAMES` to the backend |
| `Dockerfile.backend` / `entrypoint.sh` | Leader image — creates hardware YAML, DB, calibrations, registers workers, clears stale MQTT states, starts Huey + MQTT-to-DB + Flask |
| `Dockerfile.worker` / `entrypoint-worker.sh` | Worker image — same setup but no DB init, no MQTT-to-DB streaming |
| `local_app.py` | Wraps upstream `create_app()` with SPA catch-all + MQTT broker address rewrite (`mosquitto` → `localhost`) |
| `worker_app.py` | Thin wrapper around `create_app()` |

## Development commands

```
WORKER_COUNT=3 ./compose.sh up --build              # full stack with 3 workers (leader always included)
./compose.sh down                                   # stop stack
./compose.sh exec backend pio run <job>             # launch job
./compose.sh exec backend pio kill --all-jobs       # kill all jobs
./compose.sh exec backend pio logs -n 10            # recent logs
./compose.sh exec backend pio mqtt                  # live MQTT feed
```

`compose.sh` accepts any `docker compose` command: it uses `-f docker-compose.yml -f .compose-workers.yml` and passes the remaining args as-is.

## Config & state

- `.pioreactor/config.ini` — leader config. Tracked in git. `compose.sh` syncs its `[cluster.addresses]` with the active workers.
- `.pioreactor-worker/config.ini` — worker config (points `cluster.topology.leader_address=backend`). Tracked. It is the template for `worker01`.
- `.pioreactor-worker-worker0N/` — extra worker configs (worker02+), generated by `compose.sh` from the template and fully gitignored.
- `.gitignore` treats `storage/`, `hardware/`, `ui/`, `plugins/`, `exportable_datasets/`, `experiment_profiles/` as ephemeral (regenerated by entrypoints). Worker dir is almost entirely ephemeral except `config.ini`.
- Both `config.ini` files set `broker_address=mosquitto` (Docker DNS).
- Entrypoints auto-create hardware YAML, SQLite DB, calibrations, worker registrations, and clear stale retained MQTT states on each start.

## Testing

- `./compose.sh exec backend pytest core/tests` (runs upstream Pioreactor tests inside container).

## Gotchas

- Run `docker network create lab-network` before first `./compose.sh up`.
- `local_app.py` rewrites `broker_address=mosquitto` → `localhost` in `/api/config/shared` so the browser JS can reach MQTT via WebSocket on `:9001`.
- `test-mqtt-cli` contains a one-shot `mosquitto_pub` command to inject fake OD data for manual testing.
